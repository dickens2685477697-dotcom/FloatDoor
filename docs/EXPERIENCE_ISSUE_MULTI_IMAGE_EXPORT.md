# 体验问题记录：多张图片导入后仍需逐张拖出

记录日期：2026-08-24  
产品：Float Door  
场景：图片批量导入后，向 Finder / 网页输入框导出

## 现象

一次导入多张图片后，当前交互仍以单张卡片为单位完成拖出。用户需要重复“选中一张 → 拖出 → 返回 → 再选下一张”，图片数量越多，重复操作越明显。

截图证据：`/var/folders/cj/yv248yy119s2kwxxs7crvn_h0000gn/T/codex-clipboard-f9e98a7d-4fbb-491d-8135-2ce38135a657.png`（用户提供；红框是待点击区域的标注，不是最终选中态）。

## 影响

- 入口已经接受了多张内容，出口却被拆成逐张操作，输入规模与输出规模不一致。
- 卡片是否被选中缺少明确的状态反馈，用户不容易建立“我正在操作哪一张”的把握。
- 逐张拖出会打断连续工作流，也让批量导入的价值没有在导出环节兑现。

## 迭代假设

如果把卡片作为桌面文件夹里的“文件”来处理，给它清晰的选中态，并复用 macOS Finder 的 `⌘` / `Shift` 多选习惯，那么用户可以先组织选择，再一次性完成拖出，减少重复往返。

## 迭代方案

1. 鼠标点击卡片主体（问题截图中的红框标注区域）后显示明确的蓝色选中反馈。
2. 按住 `⌘` 点击可切换多个不连续卡片；按住 `Shift` 点击可选择连续范围，行为参考桌面文件夹。
3. 多选后从任意选中卡片拖出，作为一组交付全部选中图片；单张拖出继续可用。

## 验证清单

- 导入 3 张以上图片，单击任一卡片后只显示该卡片的蓝色选中反馈。
- 使用 `⌘` 选择不连续卡片，使用 `Shift` 选择连续范围；选择数量与视觉反馈一致。
- 从任意选中卡片开始拖拽，目标位置收到全部选中图片，且每张只出现一次。
- 单张拖出、展开/收起、归档等原有卡片操作不受影响。

## 迭代结论（已实现并完成工程验收）

这不是单纯增加一个批量按钮，而是把“导入多张 → 组织选择 → 一起拖出”补成连续闭环。当前实现已覆盖蓝色卡片选中反馈、`⌘` / `Shift` 多选和成组拖出；最终回归共 22 项测试通过，覆盖拖动已选项时保留整组选区、每个选中项生成一份独立拖拽载荷、跨区域选择解析和右键菜单穿透。发布前仍建议在真实 Finder 目标中补做一次端到端拖放手测。

作品集案例与小红书帖子以“发现问题 → 解释原因 → 设计选择 → 验证标准”的顺序记录这次迭代，便于后续继续补充真实使用反馈。
